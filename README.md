# Model_concierge 🤵

Локальный «дворецкий» зоопарка диффузионных моделей: сканирует папку `models\`, по тензорам определяет, **что** за файл перед ним, раскладывает всё по папкам, собирает правильные команды для `stable-diffusion.cpp` и гоняет их **очередью** через веб-морду в стиле консоли. Один файл Python + стандартная библиотека. Без GPU: всё считается на CPU.

## ✨ Особенности

- **Сканер и классификатор** — читает заголовки `safetensors`/`GGUF` и по именам тензоров определяет роль файла (чекпоинт / DiT / LLM-энкодер / VAE / LoRA / motion-модуль / ESRGAN). Имя файла — только подсказка: **тензоры важнее имени**.
- **Лечащая раскладка** — кнопка «Раскидать по папкам» перемещает файлы в правильные подпапки и чинит ошибочно разложенное.
- **Конструктор команд** — выпадающие списки: конвейер → модель → режим → промпт → лоры (чекбоксы) → «Собрать команду» → «в очередь».
- **Очередь с воркером** — задачи выполняются последовательно, логи пишутся в `queue_logs\`, статусы и живой хвост лога — в морде (автообновление 5 с). Очередь переживает перезапуск (`queue.json`).
- **Авто-добавки в промпт** — базовое качество + триггеры лор: из ручного словаря `TRIGGERS` и **автоматически из метаданных лоры** (`activation_word`, `ss_training_comment`, `ss_tag_frequency`).
- **Подсветка совместимости** — SD-лоры помечаются тегами `SD15`/`SDXL`; чужая для выбранного конвейера лора — полупрозрачная с красным тегом.
- **«Узнать промпт»** — достаёт промпт из метаданных PNG через `sd-cli -M metadata`, а если метаданных нет — просит Qwen2.5-VL (порт 8081) описать картинку как промпт.
- **Именование выходов** — `dreamshaper_8+snofs_krea_v1_3D_img.png`: разные наборы лор больше не перезаписывают друг друга.

## 🛠️ Стек технологий

- **Frontend**: HTML/CSS/JavaScript (веб-морда через `ThreadingHTTPServer` на порту 8090)
- **Backend**: Python (только стандартная библиотека: `http.server`, `base64`, `difflib`, `json`, `re`, `subprocess`, `urllib`)
- **База данных**: `queue.json` (очередь задач)

## 🎯 Использование

Откройте веб-морду в браузере по адресу `http://127.0.0.1:8090`. Основные функции:

- **Сканирование** — кнопка «Скан» (`scan()`) перечитывает папку `models\`, анализирует каждый файл (`analyze_file()`) и классифицирует по тензорам (`classify()`, `classify_by_tensors()`).
- **Раскладка** — «Организация» (`organize()`) перемещает файлы в правильные подпапки.
- **Конструктор команд** — выберите конвейер, модель, режим, промпт и лоры-чекбоксы, затем «Собрать команду» (`build_one()`) и «В очередь» (`add_job()`).
- **Очередь** — задачи выполняются воркером (`worker()`); логи пишутся в `queue_logs\`, статусы и хвост лога (`read_tail()`) отображаются в морде.
- **Узнать промпт** — `read_metadata()` достаёт промпт из PNG-метаданных; `ask_vl()` просит Qwen2.5-VL (порт 8081) описать картинку.

## ⚙️ Конфигурация

Настройки залиты в код:

- **`TRIGGERS`** — ручной словарь триггеров лор для авто-добавки в промпт.
- **`OUTPUT_DIR`** — директория всех выходных и входных файлов (все файлы одной команды — в `OUTPUT_DIR`).
- **Порты** — веб-морда на `8090`, Qwen2.5-VL на `8081`.
- **Wildcards** — конфигурационный YAML (терпимый парсер `wc_load_yaml()`, `wc_validate()`): имя, источник, папка-группа, примеры.
- **Режимы** — `SD1.5` / `SDXL` (определяются сигнатурами тензоров через `lora_family()`).
- **Кэш** — `civ_load_cache()` / `civ_save_cache()` / `civ_query()` / `civ_enrich()` — кэш совместимости лор.

## 🔧 Решение проблем

- **`sd-cpp` не найден** — убедитесь, что папка `D:\AI_Servers\sd-cpp` установлена рядом; команды `sd-cli` выполняются через `subprocess`.
- **Очередь не выполняется** — проверьте, что воркер запущен в консоли (`Concierge на http://127.0.0.1:8090, воркер очереди запущен`) и что `queue.json` доступен для чтения/записи.
- **Нет промпта** — если метаданных PNG нет, Qwen2.5-VL на порту 8081 должен быть запущен; проверьте доступность порта.
